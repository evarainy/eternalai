# MCP 上线待测与启用清单

这是上线准备清单，不是生产部署或真实业务写授权。未勾选的公司合同与真实环境项保持待测。先完成 [公司确认台账](mcp_company_questions.md)，离线证据边界见 [离线验收](mcp_offline_acceptance.md)。

## 固定配置与装配

- [ ] 为每个服务指定稳定 `service_config_id`、版本、deployment、tenant、issuer/resource、固定 MCP/注册/授权/token 地址和精确 callback/version。配置仅允许 HTTPS 或明确 loopback 测试 HTTP；不含真实 token。两个同名工具必须映射不同服务 Capability ID。
- [ ] 由配置负责人通过既有安全配置渠道提供 `MCP_SERVICE_CONFIGS_JSON`，解析为 `Settings.mcp_services`；代码默认空列表、最多 16 个 profile，profile 默认 disabled。不得把本地替身配置复制为正式配置。
- [ ] 配置变化先分析旧注册、旧 grant、UNKNOWN 制品及未决操作；存储会拒绝同 profile 的静默配置漂移。批准版本升级/兼容恢复方案后再迁移，不能删除重建或更换 client 来绕过旧制品约束。
- [ ] 确认既有加密密钥安全供应及备份恢复流程。真实凭证仅进入环境/秘密渠道，不贴日志、截图、报告或 PR。
- [ ] 取得正式 DB 迁移专项授权，核对两份 MCP revision、备份和回退约束后执行；隔离测试库通过不构成正式迁移批准。已有业务记录时降级保护必须生效，不删除 UNKNOWN/有效 grant。
- [ ] 在 `build_production_components` 注入经签收的 `mcp_identity_policy`、按 `(service, tool)` 键控的 `mcp_contracts` / `mcp_recovery_policies` / `mcp_submit_preconditions`，以及必要的 `mcp_task_rules`。两个 submit 的独立前置许可默认缺失；未配置的插口继续拒绝，`mcp_isolated_test_contracts` 正式环境保持 false。
- [ ] 用代码拥有的 catalog 生成并审阅描述符/ToolBinding，经既有 Registry 管理流程显式写入批准版本并核对输入/输出/政策摘要。19 个描述符不是 19 个远端工具；内部六叶不得出现在普通候选中。

## 普通用户授权与读取

- [ ] `/apps` 仅显示当前用户服务与连接，授权操作经过 CSRF；用真实普通用户完成 PKCE、issuer/state、单次回调、正确 client/resource 和同人断言。
- [ ] 两个不同用户、同一用户两个服务、两个登录会话分别验证连接/代次隔离。交换服务/连接/Capability、重复回调、跨用户查询操作均拒绝。
- [ ] 逐一验证七读的正常、空、分页、受限、截断、不可用，核对 model/UI/persistence 白名单；不以未查到数据证明义务完成。
- [ ] 实测授权过期、撤销、注销和主动断开；旧调用/旧确认不可继续发送。客户端注册复用，DCR 结果丢失停止注册并人工核对。
- [ ] 审核代理/SDK/HTTP/server access 日志，不记录授权码、回调 query、Cookie、token 或原业务正文；确认有界错误输出在真实部署生效。

## 六写逐项受控验收

只有取得对应真实写动作授权后执行，每个工具记录获准主体、原制品及可验证后态。六项分别是 preview、clothing submit、preparation save、record draft save、record submit、task claim；不能用其中一项代替其他项。

- [ ] 本地确认绑定用户/租户/登录、服务/版本、连接/代次、client、原参数摘要、Capability/政策版本及有效期；变更任一项后旧确认失效。
- [ ] 两个 submit 仅在经验证的本人外部确认，或经专项批准且有证据的提供方原子拒绝保障下执行；打开审核页、点击本地确认、HTTP 200 都不能单独证明完成。
- [ ] 三种非幂等创建响应丢失后停止新增，用公司批准流程核对原制品；“未找到”不自动视为未保存。
- [ ] submit/claim UNKNOWN 先通过原回执/记录/mine 查询获得充分证据。获批允许再次发送时，还需原制品或任务资格有效期的可信依据，仍绑定原制品/原参数/client，重新本地确认，并以新的一次许可发送；空期限不代表无限有效。
- [ ] 从真实聊天确认故障返回进入 `/apps`，本人操作列表和安全摘要可用；活跃 SENDING 的显式恢复被拒，进程退出后才能转 UNKNOWN，GET 与恢复均不产生业务写。
- [ ] 以真实环境允许的故障方式验证断流/超时、并发重复确认和进程恢复，记录远端实际次数。禁止为了测试无授权地制造业务副作用。
- [ ] 换登录后的接管必须由批准同主体政策验证；换号、换 client、过期制品拒绝，重授权不延长原制品期限。
- [ ] 逐一核验被服提交/发放/交接、谈话准备/正式记录/计次、任务领取/完成的不同事实，未获证据的状态不得显示成功。

## 运维与暂停

- [ ] 批准操作/回执/加密正文的最小保留期、人工结案和清理方案。当前没有自动清理未决恢复记录的任务；任何删除须有明确范围和授权。
- [ ] 正式容量、SSE 代理缓冲、最大响应/时限、撤销延迟和可观察性完成实测。队列与全局/连接并发限制不得因限流而临时绕过。
- [ ] 关闭能力时保留原注册和恢复依据。出现身份不明、输出漂移、权限不足、网页确认不能证明、UNKNOWN 无法核对或不可控重复调用，暂停受影响能力；取消本地等待不能撤销已发送业务写。
- [ ] 完成 required checks、独立自审/Monitor/静态审核和最终候选绑定后，按获准集成路线发布。真实服务验收另留证据，不核销原 OA 必达链或第二租户禁启限制。
