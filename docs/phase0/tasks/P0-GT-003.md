## 9. Constraints to Carry Forward

- 本任务是 **type=review**，禁止任何生产代码修改；`app/`、`web/` 均在 `forbidden_paths`。
- 验收报告中所有证据必须来源真实命令输出，不得编造通过状态。
- `not_applicable` 必须填写完整字段（spec Task Record schema 规定的 5 个子字段），不得用空字符串掩盖失败。
- Golden Task ID 命名约定区分：**P0-GT-00x** 是 Phase 0 任务 ID（本任务书用），**GT-0xx** 是 fixture ID（fixture 文件名和 runner 输出用）；行文不得混用。
- 报告必须明确区分「正向通过率」和「负向/边界/安全拒绝路径通过率」两个独立指标，两者均须达标才能 go。
- P0-INFRA-005 的特殊情形处理（§2.2）不可省略。
- 证据不可复现（§3.4 附录缺失、§2.8 CI 不一致、§10 复跑不一致三者任一）→ 不得给出 go 结论。

## 10. Review 复跑对账（review 阶段强制，必须真实运行）

文字审查（契约逐项对账）照常进行，但**不构成 review 通过的充分条件**。review 通过的必要条件是复跑对账：

```yaml
review_rerun_contract:
  rerun_required:
    - "uv run pytest"                                        # 全量
    - "uv run python scripts/run_golden_tasks.py --summary"
  rerun_actor: "method_profile.review_owner（Codex）；若 reviewer 运行环境受限，由调度方（orchestrator）复跑并把原始输出交 reviewer 对账"
  forbidden_actor: "执行者（execution_owner）的自报输出不得作为对账基准"
  reconcile_against: "报告 §3.4 证据附录（通过/失败计数、各 GT 终态、通过率、exit code）"
  mismatch_action: "任何不一致 → REQUEST_CHANGES；禁止以报告文字为准"
  record: "复跑命令、exit code、时间戳、git SHA 写入 review 结论"
```

判定规则：

- 复跑结果与证据附录一致 → review 才可进入文字结论阶段。
- 复跑 failed 但报告记 passed → blocker，按虚报处理：整体 no-go，并在 review 结论中追溯原因。
- 复跑因环境缺失无法执行（如 uv / Python 环境不可用）→ 该项按 not_applicable 五字段规则记录，不得默认采信报告数字。
