## 目标（done_when）

1. 仅 `adapter_timeout` 属于代码常量声明的可重试白名单；固定最多重试一次，共两次
   Gateway 调用。其余错误零重试。
2. 重试耗尽或不可重试失败后立即进入 `failed` / `timeout` 终态，后续 step 对 Gateway
   与 Adapter 零调用，Gateway 的 `error_code` 保真。
3. Runtime 不再把 Workflow 失败兜底成 completed；失败路径无 `task_completed`。
4. 每次重试在 Workflow/step 证据中带 attempt 与 retry_number；
   `adapter_error_mapped` 仍由 Gateway 独占。
5. confirm 恢复中途失败后清除 engine checkpoint 与 Runtime pending；waiting 行为不变。
6. 新增 Trace/TaskStore 证据只含固定元数据和 error_code，不含输入、输出或敏感值。

## 重试与幂等决策

timeout 无法证明下游未执行。本任务仅因当前 B4 范围限定 Mock/低风险能力且明确排除真实
业务写，批准 `adapter_timeout` 一次重试；这不是生产代码中的 Mock 隔离机制。真实写能力
接入前必须重开幂等契约，不能继承此白名单。`adapter_error`、`adapter_http_500`、权限错误
及所有确定性错误均不重试；不引入 per-step 配置、退避、时钟、队列或幂等框架。
