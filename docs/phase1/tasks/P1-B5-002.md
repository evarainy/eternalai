## 实施前 Gap Map

### 1. 知识数据形态与位置

- 在 `app/knowledge/` 新增不可变 `KnowledgeItem` 与具体 `BasicKnowledge` 组件。
- 企业术语、Mock 系统说明、制度模板是模块级 tuple 常量；不提供写 API，不读取
  外部文件、DB 或网络，也不按 tenant/session/user 分区。
- 仅做关键词包含的确定性查表和稳定排序；不引入向量、embedding、RAG、重排、
  热更新或可插拔知识源。

### 2. 能力说明的唯一来源

- Runtime 每次请求通过现有 `CapabilityRegistryPort.list()` 读取当前 Registry 快照，
  再交给 `BasicKnowledge` 生成能力说明；代码内不保存 capability id 清单。
- 说明只使用 Registry 的 capability id、type、target system 与 status；不读取或注入
  short_description、name、owner、intent_tags、schema 等自由文本。Registry 变更后
  下一次请求的结构说明随之变化。
- `_select_capability` 仍是唯一授权/解析路径；知识不调用 Gateway，不创建、启用或
  注册 Capability，也不改变 exact-id / unique-active-intent-tag 规则。

### 3. IntentRouter 注入边界

- `IntentRouter.parse(..., knowledge_items=())` 接收本次只读快照；最终注入点硬限制为
  `MAX_KNOWLEDGE_ITEMS = 8`、`MAX_KNOWLEDGE_ITEM_LENGTH = 240`。
- 8 条足以承载少量静态命中和小型能力概览，240 字符足以描述一条静态事实或
  Registry 结构说明，并把 IntentRouter 的最终知识输入面锁在小范围内。
- 超限按稳定输入顺序截断，不拒绝请求；精确测试第 9 条消失、每条恰为 240 字符。
- 知识使用独立 system 消息；Session Memory 保持自己的独立 system 消息，顺序为
  base intent → knowledge → memory → user，二者使用不同 JSON key，互不覆盖。

### 4. 无能力终态引导

- `_finish_no_capability_found` 保持 task `no_capability_found`、error code
  `capability_not_found`、blocked/failure Trace 终态完全不变，只扩充可读 message 与
  fallback text。
- 引导在终态发生时重新调用 `Registry.list(status="active")`，并在组件内再次校验
  `status == "active"`；仅显示当前 active 能力和 `Admin Lite > Registry` 配置入口，
  明示系统不会自动创建或执行未注册能力。disabled/deprecated/draft 均不出现。

### 5. Mock LLM 下的诚实证据边界

- 无法诚实断言“自然语言命中知识后导致模型选择某能力”：Mock LLM 只按最后一条
  user 消息查表，system knowledge 不影响返回。不会编写此类命中率测试。
- 替代证据为三组：`BasicKnowledge` 关键词查表及 Registry 派生的纯函数断言；
  `mock.calls[-1]["messages"]` 的来源、结构、条数、长度和隔离断言；Runtime 对
  disabled / 不存在 selector 的真实 Registry 复核、零 Gateway 调用和失败终态断言。
- LLM 返回值断言只证明结构化输出链仍工作，不冒充知识效果证据。

### 6. 敏感值过滤点

- 静态知识只含通用组织术语和 Mock/制度模板，不含凭证、真实地址或真实人名。
- `BasicKnowledge` 不读取 Registry 的任何自由文本；capability id 只允许最多 96 个
  ASCII 字母数字及 `._-`，不合格或含敏感 marker 时整字段替换为 `[REDACTED]`。
- `sanitize_knowledge_text` 规范化后，只要整条命中敏感 marker、URL/UNC、邮箱、IP
  或人名标签就整条返回 `[REDACTED]`，不尝试保留“安全部分”。IntentRouter 在最终
  注入前复用同一纯函数，再应用条数/长度限制；知识不写入
  Trace、Task Record runtime state 或 Session Memory。无能力响应也只使用已清洗的
  active 结构摘要；测试同时扫描 prompt、Trace、task state 与 envelope。

### 7. Gap 与决策

- 真实 Gap：缺少基础知识组件、IntentRouter 知识消息、Runtime Registry 快照接线、
  无能力 Admin Lite 引导，以及上述可证伪测试与 knowledge import boundary。
- 非 Gap：不需要 Port 变更、新依赖、外部引擎、队列、DAG、向量库或信任边界变更；
  不改 B5-001 Memory 隔离语义、Policy/Identity/Gateway/Workflow 或 Golden。
- `app/composition.py` 只在既有参数尾部新增可选具体组件参数，不重排任何参数。
