## 实施前 Gap Map

### Trace 落点与契约决策

- 选择扩 `TraceEventType`，新增独立 `evaluation_recorded` 事件；不把评测塞入
  `task_completed` / `task_failed` attributes。
- 独立事件使同一 task 的业务终态与 Evaluator 结论可分别查询，直接满足 S-B5.3；
  只扩事件枚举，不新增 Trace 方法，既有 writer 的通用 `record_step` 路径保持不变。
- 结论 attributes 固定为 `rule_id`、`business_status`、`business_error_code`、
  `evaluation_result`、`reason`；Trace 顶层继续保留业务 `error_code`。

### 完整映射

| business_status | evaluation_result | reason |
|---|---|---|
| `completed` | `passed` | `business_completed` |
| `failed` | `failed` | `business_not_completed` |
| `denied` | `failed` | `business_not_completed` |
| `binding_required` | `failed` | `business_not_completed` |
| `timeout` | `failed` | `business_not_completed` |
| `no_capability_found` | `failed` | `business_not_completed` |
| Evaluator 抛异常 | `error` | `evaluator_error` |

`waiting_user` 不是终局，不进入 Evaluator，也不生成 `evaluation_recorded`。

### 三条终局接线与故障处理

- 主链执行与 Workflow resume 分别在业务终态事件之后、Trace finalize 之前记录；
  两处 waiting 分支均跳过 Evaluator。
- `_finish_no_capability_found` 在既有 `task_failed` 之后、finalize 之前记录。
- Runtime 捕获 Evaluator 异常，记录固定 `error` 结论，不记录异常类型或消息；
  ResponseEnvelope、TaskStatus 与业务 error_code 不受评测结果影响。

### 敏感值边界

- Evaluator API 只接收封闭的终态与 `ErrorCode`，不接收 message、arguments 或
  `exec_result.data`；评测 attributes 不存在原始业务载荷入口。
- 异常消息不进 Trace，因此异常文本即使含 credential sentinel 也不会泄漏。

### Gap 与非 Gap

- 真实 Gap：纯规则 Evaluator、三处终局接线、独立 Trace 事件、映射/对照/故障/
  敏感值/三路径测试，以及 evaluator import boundary。
- 非 Gap：不需要 LLM、通用策略框架、新依赖、外部服务、重试、控制动作、Admin
  Lite、Golden 扩充，且不改 Policy/Identity/Gateway/Workflow/Memory/Knowledge 语义。
