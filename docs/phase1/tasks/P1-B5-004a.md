## 实施前 Gap Map

### 授权判定与角色来源

- 复用 `PolicyGuardPort.decide`，不新增第二个授权 Port。当前
  `RequestOrgContext` 已有 `roles`，因此管理动作可以沿用同一 Policy 判定点。
- 只允许 `admin_registry_list/get/create/enable/disable` 五个显式动作；其他
  `admin_*` 即使声明 `admin` 也拒绝，避免放宽 Gateway 可见能力。
- 角色来自 `X-EternalAI-Roles` 请求头，是未经认证的请求声明；Trace 固定记录
  `role_claim_authenticated=false` 与 `role_claim_source=request_header`。真实部署前
  需前置认证。
- Golden 的 `given.roles` 仅参与 fixture schema 校验，harness 没有读取它；本任务
  没有复用一个已存在的角色机制。

### 路由、接线与安全响应

- `make_router(admin_service)` 注册到 `/api/v1/admin`；`create_app` 只增加可选
  Admin service 参数，`app/composition.py` 只增加 builder，不重排 Runtime 接线。
- Admin service 的构造依赖只有 Registry、PolicyGuard、Trace；不依赖 Gateway、
  Adapter、Runtime、Workflow 或 Infra。
- 未声明管理角色时，所有读写在访问 Registry 前返回同形 `403 role_not_allowed`；
  已有与不存在资源不产生差异。授权后不存在才返回 `404 capability_not_found`。
- 返回专用 `AdminCapabilityView`，排除 `input_schema`、`output_schema`、
  `policy_digest`，只暴露 Registry 元数据和 schema digest。

### 受控动作与状态转换

| 动作 | 前态 | 后态 | 语义 |
|---|---|---|---|
| create | 不存在 | `draft` | 请求体不接受 `status`，service 固定构造 draft |
| enable | `draft` / `disabled` | `active` | 独立启用动作 |
| enable | `active` | `active` | 幂等 |
| disable | `draft` / `active` | `disabled` | 受控停用 |
| disable | `disabled` | `disabled` | 幂等 |
| enable / disable | `deprecated` | 不变 | `409 invalid_status_transition` |

### Trace 与拒绝形状

- `TraceEventType` 新增 `admin_action`；成功用 `ok`，Policy/角色拒绝用
  `blocked`，不存在或非法状态转换用 `failed`。
- attributes 只含 action、Policy 结果、前后状态与角色声明来源/认证状态，不写
  请求 body、Registry 内容或角色值。
- 读写拒绝固定返回 `{"detail":{"code":"role_not_allowed",
  "message":"Management role is required."}}`，不泄漏资源是否存在或内容。

### 验证边界

- API 测试在成功与拒绝路径注入 `Runtime -> Gateway -> Adapter` 串联 sentinel，
  三层都必须保持零调用；误接执行链时测试必须变红。
- architecture 规则禁止 `app.admin` 导入 Gateway、Adapter、Runtime、Workflow、
  Infra；Admin API 只调用 service。
- 既有全量测试与 Golden 23/23 证明 B2-B4 Gateway / Identity / Policy 行为不变。
