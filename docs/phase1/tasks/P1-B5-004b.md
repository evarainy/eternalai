## 实施前 Gap Map

### TaskStore 读取契约

- `TaskStorePort.list_tasks(*, session_id=None, ai_user_id=None)` 支持按 session、用户或
  两者交集查询；至少提供一个过滤条件，避免形成全表管理台账。
- `TaskStorePort.list_events(task_id)` 按 Task 读取事件序列。两类数据均已存在于
  `tasks` / `task_events`，只扩读取契约与 PostgreSQL 实现，不做 schema 变更。
- 两个查询都在实现内固定最多返回 100 条，不提供可由 API 调整的 limit 参数；Task
  按 `task_id`，事件按 `timestamp, event_id` 确定性排序。
- 同步更新 Runtime 测试中的 11 个 TaskStore fake 与 WorkflowEngine 的专用 fake，
  避免测试替身落后于 Port。

### 三类响应的字段白名单

| 响应 | 白名单字段 |
|---|---|
| Task | `task_id`, `session_id`, `ai_user_id`, `status`, `capability_id`, `error_code` |
| Task event | `event_id`, `task_id`, `event_type`, `timestamp`, `evidence` |
| Binding | `binding_id`, `target_system`, `execution_identity`, `bind_status`, `binding_scope`, `account_set_id`, `device_domain_id`, `reason_code` |

`evidence` 不是原始 payload，只接受当前生产事件的显式字段：`capability_id`,
`selection_rule`, `workflow_id`, `workflow_version`, `workflow_status`, `error_code`,
`step_id`, `step_index`, `step_status`, `attempt`, `retry_number`, `max_attempts`,
`waiting_step_id`, `waiting_step_index`, `confirmed_capability_id`,
`completed_step_ids`, `step_output_keys`, `recovery_input_keys`。未知 payload 字段丢弃。
Task 响应不暴露 `trace_id`。

### Binding 查询约束

- `ai_user_id` 必填，可选 `target_system`, `binding_scope`, `account_set_id`,
  `device_domain_id` 过滤；只调用现有 `IdentityMappingPort.list_mappings`。
- 不扩 `IdentityMappingPort`，不提供全局 Binding 台账；服务边界固定截断为 100 条。

### 授权、Trace 与拒绝形状

- 闭合动作表新增 `tasks_list -> admin_tasks_list`、
  `task_events_list -> admin_task_events_list`、
  `bindings_list -> admin_bindings_list`。
- 三个动作复用既有 `AdminRegistryService._authorize`、`MinimalPolicyGuard` allowlist
  与 `_record` Trace 路径；授权发生在访问 TaskStore / IdentityMapping 之前。
- 无管理角色固定返回
  `403 {"detail":{"code":"role_not_allowed","message":"Management role is required."}}`，
  不因 Task、事件或用户是否存在而变化。授权后 Task 不存在才返回
  `404 task_not_found`。
- Trace 继续诚实记录角色来自请求头且未经认证；不记录查询内容或角色值。Trace 当前
  不持久化，仍由 `P2-TRACE-PERSIST-001` 承担，本任务不另造记录路径。

### 执行面与验证边界

- Admin service 只增加 `TaskStorePort` 与 `IdentityMappingPort` 依赖，不依赖或调用
  Runtime、Gateway、Adapter、Workflow。
- 三个新路由的成功/拒绝测试均锁定 Runtime、Gateway、Adapter 零调用；architecture、
  既有 Runtime 对照与 Golden 证明 B2-B4 顺序不变。
