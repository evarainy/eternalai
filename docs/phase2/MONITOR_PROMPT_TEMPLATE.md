# Phase 2 · 监理提示词模板

按 `AGENTS.md`「Git、Review 与授权」中监理条款生成。**监理是独立执行取证方，不是第二个读代码的人**：靠读代码就能判定的项一律归 Opus，不得写进本提示词。

用法：整份复制，替换 `<...>` 占位，落到 `_scratch/<task_id>_监理.md`（返修轮次加 `_r2` / `_r3` 后缀），交给独立 codex 窗口。

---

## 模板正文

```markdown
# <task_id> · 独立执行取证复核<（第 N 轮）>

你是独立取证复核方，对本仓库自己的代码做验收取证。**只取证、只报结论，不改交付内容。**

- 工作树 `<worktree_path>`
- candidate = `<candidate_sha>`，base = `<base_sha>`
- 任务合同：`<启动提示词绝对路径>`
- <返修合同：`<返修提示词绝对路径>`>
- 执行方自审：`<自审结论绝对路径>` —— **先自己取证，最后才读**

本棒做的事：<一到三句话，说清改了什么、走哪条路径、边界在哪里。不复述实现细节。>

## 必做取证（四类，全部要求亲手执行）

### 1. 变异与故障注入
<逐条列出本棒必须证伪的形态。每条写成「把 X 改成 Y，某某门禁应当变红」。>
把改动按上述形态收窄或回滚后，对应门禁**必须变红**；仍绿即判 FAIL。每次改写前记录可还原基线，验证后立即精确还原。

### 2. 测试数据充分性
<列出本棒 fixture / 被测输入里，取值可能恰好让守卫失效的地方。>
判据：fixture 的取值是不是碰巧构造出了守卫能看见的场景？请改动 fixture 取值重跑，证明守卫覆盖的是**合同要求的全集**，而不是这一组特定取值。证伪不成立即判 FAIL。

### 3. 依赖保真度
<列出必须走真实依赖的断言：真实 PostgreSQL / 真实授权路径 / 真实 migration 往返 / 真实 HTTP 边界。>
确认这些断言不是替身、不是内存 fake、不是被 monkeypatch 短路的路径。

### 4. 数字复核
自己重跑 <列出本棒适用的命令>，与 `docs/phase2/STATUS.md` 登记数字逐项对照。治理文档不得写 SHA / CI run / PR 号。

## 不归你的事（归 Opus，不要复核）

合同完整性、类型层可达性、授权边界与 scope 越界、目录与分层合规、声明缺失、跨文件一致性。看到这些项的疑点，写进非阻断项供 Opus 参考，**不据此判 FAIL**。

## 环境说明

<写明本机已知环境限制及其处置。例：沙箱会让 pytest 的 tmp_path 报 PermissionError WinError 5，这是已知环境限制不是缺陷，记为「因沙箱限制未核实」并继续，不判 FAIL，不改 TMP/TEMP、不加 --ignore=。>

## 纪律

每次临时改写前记录可还原基线；验证后立即还原并核对 `git status --porcelain` 为空、HEAD 仍为 `<candidate_sha>`；交结论前最后再核一次并把原始输出写进结论。不读 `_scratch/oa/` 下任何原始素材。不 push、不开 PR、不 merge、不调用外部评审、不修改 candidate 交付内容。

**已预授权**：删除本工作树内 `__pycache__/`、`*.pyc`、`.pytest_cache/`、`.mypy_cache/`、`.ruff_cache/`；动手前先跑 `git ls-files --others --exclude-standard`，为空就不删；禁用通配清理，不碰 `.venv/` 与 `_scratch/`。

## 输出

结论写入 `<结论文件绝对路径>`，**首行必须是** `VERDICT=PASS` 或 `VERDICT=FAIL`。阻断项与非阻断项分开列，每项附复现命令与原始输出。
```

---

## 生成时的检查

- 四类取证是不是都填了本棒的具体内容？空着的类要写明本棒为什么不适用，不能留占位。
- 有没有把静态项（scope、目录、契约、一致性）混进必做取证？有就删掉——那是 Opus 的活，重复复核既费钱又会互相污染判断。
- 第 1、2 类是不是写成了可判定的形态（「改 X 成 Y，Z 应变红」），而不是「请确认覆盖充分」这类不可判定的要求？
- 本棒已是第三轮监理吗？是则不再生成，按 `AGENTS.md` 停手上报。
